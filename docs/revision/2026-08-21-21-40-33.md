## 总结

项目当前已经达到可运行的 P3.2 原型水平，核心架构方向基本正确，但还不能称为生产级 Agent Runtime。

核心执行链路已经存在：


Goal → Task → Decision → Capability Resolution → Policy → Tool → Observation → Evidence → World Model → Evaluation → Finish / Recover / Fail

## 主要问题

### 高优先级：Domain Identity 校验没有真正生效

ToolRegistration 支持保存 Domain 身份，但 Runtime Builder 注册工具时没有传入身份：src/universal_agent/domain/builder.py:100-102。

Action 创建 PendingAction 时没有写入 Domain 身份：src/universal_agent/runtime/actions.py:83-89。生成 ToolCall 时也没有携带 Domain 身份：src/universal_agent/runtime/actions.py:146-152。

因此 ToolRuntime 中的 Domain mismatch 检查通常不会被 Runtime 主流程触发：src/universal_agent/tools/runtime.py:97-110。这会造成错误的安全感。建议让 Composition 为每个工具保留 owner identity，并让 PendingAction、ToolCall、Snapshot 全链路使用同一身份。

### 高优先级：多 Domain Session 恢复只保存 primary Domain

SessionSnapshot 只有单个 domain_name 和 domain_version：src/universal_agent/state/session.py:23-29。但 DomainComposition 支持多个 Domain：src/universal_agent/domain/runtime.py:81-100。恢复时只比较当前 Runtime 的 primary Domain：src/universal_agent/runtime/session.py:85-96。

结果是次要 Domain 被替换时可能仍然恢复成功，无法证明原始执行环境完整一致。建议保存并比较完整的 tuple[DomainIdentity, ...]。

### 中高优先级：多 Domain evaluator 选择逻辑不完整

Composition 会收集全部 evaluator：src/universal_agent/domain/runtime.py:142-145，但 Observation Processor 永远只解析第一个 evaluator：src/universal_agent/runtime/processing.py:72。第二个 Domain 的 evaluator 实际不会参与判断。

应让 Task、Capability 或 Domain owner 明确指定 evaluator，或者实现组合 evaluator；在此之前也可以明确禁止多 evaluator composition。

## 符合预期的部分

以下架构原则已经基本落实：

- LLM 不拥有任务、世界、证据和完成状态。
- LLM 不直接控制 Runtime 控制流。
- Capability 与 Tool 已经分离。
- Policy 在模型之外执行。
- Tool 成功不会直接等于 Task 成功。
- Evidence 和 World Model 有独立抽象。
- Recovery 有预算，不是无限重试。
- Session 可以通过 Snapshot 重建。
- Kernel 没有 Kubernetes 专用分支。

## 成熟度判断

项目当前更准确的定位是：

> 设计严肃、核心循环完整、测试覆盖不错的内存型 Agent Runtime 原型。

还不是可直接用于生产的 Universal Agent Platform。持久化数据库、Runtime API、agentd、取消和并发调度、Event Stream、OpenTelemetry、真实多 Domain 运行、真实 Kubernetes API、Evaluation Harness、Replay 和 deterministic mode 尚未完成；README 已明确说明这些处于后续阶段，因此不应视为 P3.2 的实现缺陷。

## 优化建议

1. 修复 Domain Identity 的全链路传递，并增加跨 Runtime、跨 Composition 恢复测试。
2. 设计完整的 DomainCompositionSnapshot，禁止只保存 primary Domain。
3. 明确 evaluator 的归属和选择规则，补充真正的双 Domain 集成测试。
4. 增加持久化 StateStore、EvidenceStore 和 EventStore。
5. 将 Runtime 事件改成稳定的枚举或显式事件契约，减少裸字符串。
6. 为 Tool 参数增加显式 schema 校验，而不只是检查 required keys。
7. 增加取消、并发、重复执行、进程重启、幂等和事件顺序测试。
8. 修复格式门槛，并让全新环境可以直接执行测试。
9. 将 Manifest Loader 与 Domain Package Loader 分离，支持未来独立安装的 Domain Package。
10. 在进入 Multi-Agent、Web UI 和分布式调度前，优先完成持久化、事件流、审计和 deterministic replay。
